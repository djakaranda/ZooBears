# ZooBears — даты, ASR-аугментация и проверка поставки

База кода — `d7a27749340e27e2a8d07522286ce27c353287ed`. Для разработки использован прежний сплит train по аккаунтам, seed 42. В fit 3 334 звонка, во внутреннем dev 592, пересечений по аккаунтам нет.

## Сроки и договорённости

API объединяет соседние подтверждения одной договорённости об одном объекте. Если клиент подтвердил день, а оператор явно назвал ещё и время, факт сохраняет полное окно. Реплика-источник остаётся буквальной цитатой. Два явно разных срока и факты разных объектов сохраняются отдельно. Отказ клиента подавляет и предложение, и ошибочно выделенную договорённость из реплики отказа.

На 592 dev-звонках использованы одни и те же предсказания CPU-модели, обученной только на fit. Сами факты выделялись один раз, менялись правила обработки дат и подтверждений. Внешний val использован после проверки этапа на dev.

| Правила на dev | Precision | Recall | Temporal | State |
|---|---:|---:|---:|---:|
| Исходные | 0,3929 | 0,3029 | 0,3712 | 0,2450 |
| Обновлённые | 0,3967 | 0,3011 | 0,3722 | 0,2450 |

## Внешний val

Проверка quality проведена на тех же сохранённых весах и на одном устройстве Apple GPU (MPS), с исходным и обновлённым кодом. Правила по этому val не подбирались.

| Правила на val | Precision | Recall | Temporal | State |
|---|---:|---:|---:|---:|
| Исходные | 0,4890 | 0,4103 | 0,3963 | 0,3740 |
| Обновлённые | 0,4784 | 0,4087 | 0,3820 | 0,3756 |

Все 383 результата обновлённого запуска прошли проверку схемы. Temporal ниже порога 0,4005 на 0,0185. Изменения дат остаются кандидатом для доработки. Для следующей итерации потребуется воспроизвести на dev полную нейросетевую цепочку с энкодером и нормализаторами, обученными только на fit. CPU-проверка дат на dev дала слабый прирост и не предсказала результаты quality.

## Пилот ASR-аугментации

Оба энкодера начаты с upstream ruBERT `e8ed3b0c8bbf4fb6984c3de043bf7d2f4e5969ae`. Одна эпоха, seed 42, batch 64, max length 128, Apple GPU. Подвыборка содержит 408 fit-звонков из 350 аккаунтов. В ASR-запуске добавлено 102 искажённых копии, поэтому число шагов выше. Нормализатор обучен только на fit. Для шума при проверке использованы `make_stress.py --rate 0.08 --seed 43` и одни и те же 592 dev-звонка.

| Режим | Dev | Precision | Recall | Temporal | State |
|---|---|---:|---:|---:|---:|
| Контроль | Исходный | 0,0898 | 0,1980 | 0,2495 | 0,0733 |
| С аугментацией | Исходный | 0,1213 | 0,2077 | 0,3224 | 0,0649 |
| Контроль | Усиленный шум | 0,0665 | 0,1969 | 0,2327 | 0,0607 |
| С аугментацией | Усиленный шум | 0,0966 | 0,2163 | 0,3096 | 0,0681 |

На зашумлённом dev recall вырос на 0,0194. На исходном dev state снизился на 0,0084. Чтобы отделить эффект шума от большего числа шагов, нужен контроль с тем же количеством дополнительных чистых примеров. Полный ASR-refit и оценка на внешнем val для новых весов остались за пределами пилота. Образ и quality-проверка используют прежние веса.
