# Эксперимент с нейросетевой привязкой дат

Первая итерация на v2.1 дала на внешнем val Temporal 0,4123 и State 0,5040:
этого недостаточно для порогов 0,4506 и 0,5145. Резервная версия остаётся
в `artifacts/qwen_v21`; новая обучается отдельно в `artifacts/qwen_dates`.

Qwen получает реплики и таблицу дат, автоматически разобранных из этого же
разговора. Внутренний ответ расширен с шести до восьми полей: добавлены номера
начала и окончания из таблицы. Публичный JSON фактов сохраняет прежнюю схему.
Модель не генерирует произвольные ISO-даты. Несколько упоминаний одной даты
имеют общий номер, чтобы длинные разговоры не раздували входную таблицу.

Метки ссылок автоматически строятся из существующего fit. Неназванное начало
имеет номер 0; открытое окончание — 0, завершение без точной даты — -1.
Точные дни из скрытых меток, которых нет среди разобранных выражений, не
передаются модели. Интервалы вроде «в прошлом месяце» остаются неопределёнными.
На вход не попадают facts, шумовые метки и другие звонки аккаунта.

Продолжение LoRA: rank16, 10 092 544 обучаемых параметра, одна эпоха, LR5e-5,
seed42, вход3072, ответ512. Наблюдаемые ссылки на даты имеют вес3 в функции
потерь, неизвестное завершение — вес2, остальные токены — вес1. Используются
3334 fit-разговора, 266 защищённых ASR-копий и 112 синтетических записей.
Часть коротких шаблонов повторяется для усиления нужных случаев.

Предварительная проверка fit и dev: 3991 обучающее окно, 6 559 097 входных и
целевых токенов суммарно, максимальная последовательность3386, ответ354,
таблица до14 разных дат. Целевые ответы не обрезаются. На fit получены
3551 ссылка начала, 1501 ссылка окончания и1436 неизвестных завершений.

Проверяются исходная версия и два новых checkpoints на полном dev. У новых
весов сравниваются шесть режимов: резервный обработчик, только новые начала,
консервативные границы, полные границы, только новые окончания и известные
новые начала с полными окончаниями. Два последних варианта добавлены после
первого dev-сравнения эпохи, до нового val; оба checkpoint получают одинаковые
шесть вариантов. Сохранённый кеш проверяется на
совпадение с реальной генерацией. Ограничения по recall/F1 и State не дают
выбрать рост Temporal за счёт большого падения извлечения фактов.

```powershell
$env:PYTHONIOENCODING='utf-8'
$env:HF_HUB_OFFLINE='1'
.venv/Scripts/python.exe scripts/run_date_pointer_iteration.py --resume
```

Для повторения с нуля после первой итерации используйте команду без --resume.
На Windows процесс временно удерживает систему и дисплей активными: на этом
MSI выключение дисплея сопровождалось снижением лимита GPU до30Вт. Запрос
снимается при завершении; постоянные настройки питания не меняются.
Состояние: `reports/date_pointer_iteration_status.json`; журналы:
`tmp/date_pointer_logs`; прогресс: `artifacts/qwen_dates/progress.json`.
Итоговый отчёт создаётся только после измерений: `reports/DATE_POINTER_REPORT.md`.
Если выбран baseline, экспериментальные веса не разворачиваются.

## Воспроизведение

В `reports/date_pointer_environment.json` записаны версии Python, PyTorch,
Transformers, PEFT, accelerate, numpy, scikit-learn и joblib, а также SHA-256
тренера и формата. База закреплена по revision и проверяется при скачивании.
Стартовый адаптер v2.1 и исходный двухэпоховый адаптер сохранены отдельно.
Разделение по аккаунтам повторяется с seed42 командой `scripts/prepare_dev.py`.

Для повторения продолжения обучения используется новый optimizer: состояние
старого optimizer не восстанавливается. Это воспроизводимый протокол запуска
от сохранённого адаптера, а не точное возобновление прерванного шага обучения.
Seed и версии не обещают побитно одинаковые веса на разных GPU и реализациях
CUDA. Проверять повторение следует по сохранённым метрикам и схеме вывода.
Не запускайте повторное обучение в единственной копии каталога с итоговыми
весами: используйте отдельный клон проекта.

После фиксации выбранной версии дополнительный шум и чистый контроль проверяются
отдельно; затем отчёт дополняется результатами:

```powershell
.venv/Scripts/python.exe scripts/check_date_pointer_stress.py
.venv/Scripts/python.exe scripts/write_date_pointer_report.py
```

В API к датам добавляются исходные выражения с индексами реплик и span.
Неразрешённое окончание показывается как неизвестное; метаданные интерфейса
не меняют конкурсные факты. Некорректная ссылка не создаёт дату: сохраняется
факт с резервной обработкой и увеличивается счётчик ошибок внутренних строк.
