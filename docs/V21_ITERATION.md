# Итерация на обновлённом пакете

Новый официальный пакет установлен в `data/raw`, прежний сохранён в `data/releases/v1`.
Оценщик и каталог проверены по контрольным суммам. Для локального dev известная
ошибка двух вызовов set.update обходится явно включаемым адаптером; исходник
организаторов не изменён. На внешнем val используется оригинальный алгоритм без обхода.

Сравнение вариантов дат/цепочек/объектов:
`reports/v21_date_ablation*.json`. Пока на кеше dev выбран переобученный прежний
ranker: temporal 0,3868, state 0,5257. Широкий контекст и полное перестроение
цепочек ухудшили результат и рабочими не выбраны. Кеш — разведочный эксперимент;
окончательный выбор делается после свежих генераций dev.

Свежий полный dev 15 ноября: исходные веса + прежний ranker —
temporal **0,3820**, state **0,5267**; расширенный ranker с цепочками —
temporal **0,3975**, state **0,5257**. Precision **0,6018**, recall **0,5492**
не изменились. Это результаты до дообучения, не итоговый внешний val.
Полные таблицы: `reports/v21_dev_baseline*.json`.

После полного дообучения дополнительно проверяются варианты исправления только
`valid_to`: начало сохраняется, исторические интервалы не открываются заново,
конец раньше начала запрещён. Все три checkpoint сравниваются на одном наборе
вариантов. Завершённые генерации сохраняются при перезапуске этапа оценки.

Подготовлено продолжение LoRA на полном исправленном fit: одна эпоха, LR=5e-5,
8% защищённой ASR-аугментации, 112 целевых коротких примеров. Промежуточный (шаг 300) и
итоговый checkpoints сравниваются с исходным адаптером по полноценным метрикам dev.
Сохранённые лучшие по token loss веса сами по себе не определяют финальный выбор.

```powershell
$env:PYTHONIOENCODING='utf-8'
$env:HF_HUB_OFFLINE='1'
.venv/Scripts/python.exe scripts/run_v21_iteration.py --resume
```

`--resume` предназначен для этой машины с сохранёнными временными файлами и
checkpoints. Для полного повторения в новом окружении после установки зависимостей,
загрузки базы и `scripts/prepare_dev.py` запускайте `scripts/run_v21_iteration.py`
**без** `--resume`. Наличие готового отчёта в клоне не заменяет повторное вычисление.

Запуск сохраняет состояние в `reports/v21_iteration_status.json`; логи — `tmp/v21_logs`.
Перед обучением заново генерируются все 592 dev-звонка исходной моделью и
сравниваются обработчики дат. Дополнительно проверяется расширение прежнего
ranker на дальние реплики с совпадением события/объекта, включая защиту номеров
разных заявок. Код и хеш fit сохраняются рядом с новым ranker.
После фиксации конфигурации выполняются внешний val, проверка схемы, три рабочих
режима ресурсов и локальный шумовой тест с чистым контролем на тех же звонках.
Результат — `reports/V21_ITERATION_REPORT.md`. До появления этого отчёта полное
дообучение/проверка не считаются завершёнными.

Прежнее пробное дообучение четырёх звонков (`tmp/qwen_v21_smoke`) шло при
ограничении 10 Вт со скоростью 49 токенов/с. 15 ноября в 17:35 МСК повторная
проверка показала разрешённый предел 105 Вт; smoke восьми звонков
(`tmp/qwen_v21_power_smoke`) завершился со скоростью 754 токена/с.
Старый прогноз 30 часов к восстановленному питанию не применяется.
Исходный адаптер скопирован в `tmp/backups`; хеши —
`reports/v21_original_adapter_backup.json`. Его файлы не заменяются.
Пошаговые loss, LR, gradient norm, скорость и память пишутся в
`artifacts/qwen_v21/training_log.jsonl`; метрики извлечения — в dev-отчёты
для промежуточного и финального checkpoints. Автоматическая остановка после
нескольких эпох здесь не требуется: запланирована одна дополнительная эпоха.
Повторный разбор одинаковой реплики/даты внутри оценки кешируется с возвратом
копий множеств. Совпадение всех общих и поатрибутных метрик проверено на полном
сохранённом dev; сам официальный файл оценщика не меняется.
Pipeline не начинает дорогой прогон под этим ограничением без явного
`--allow-slow-gpu`. После восстановления штатного питания достаточно повторить
команду выше. Этот порог защищает время запуска и не меняет результаты модели.
