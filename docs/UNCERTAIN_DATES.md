# Неточная («плавающая») дата начала

API `/extract` возвращает `temporal_evidence` рядом с `facts`. Элемент с
`fact_index: i` объясняет начало факта `facts[i]`:

- `start.kind = exact`: в реплике есть день или дата со временем;
  `precision = day` не означает известное время суток.
- `start.kind = range`: известен календарный период возможного начала.
  `earliest` включается, `latest_exclusive` не включается.
- `start.kind = unknown`: начало не названо, неоднозначно или не удалось
  надёжно связать дату с фактом. `observed_at` — дата звонка, а не начало состояния.

Например, для звонка 14 ноября 2026 года фраза «в прошлом месяце» даёт:

```json
{
  "kind": "range",
  "precision": "month",
  "earliest": "2026-10-01T00:00:00",
  "latest_exclusive": "2026-11-01T00:00:00"
}
```

Это диапазон **возможного начала**, а не интервал действия факта. Поле
`facts[i].valid_to` не используется для хранения неопределённости.
Источники дат сохраняются в `sources` с индексом реплики, спаном и цитатой.
День уточняет месяц, если попадает внутрь периода; противоречивые даты не
превращаются в точный день. Для принятого клиентом предложения можно взять
дату из непосредственно предшествующей реплики оператора с тем же событием.
Автоматический поиск по истории других звонков пока не реализован.

Демо показывает диапазон или неизвестное начало вместо ложной точности.
Для точной даты отображается дата из связанного текстового свидетельства.
Точечная оценка модели остаётся в `facts[i].valid_from` в полном JSON; она может
отличаться от свидетельства. Это явно отдельные представления, а не улучшение
конкурсной метрики. Новые метаданные не меняют факты, их порядок, сроки и веса модели.

Обычные пакетные предсказания сохраняют прежний формат. Для выгрузки
метаданных через `scripts/predict_experiment.py` добавьте `--date-evidence`.
Для конкурсной точечной метрики выбирать новую политику дня нужно отдельным
экспериментом на train/dev; этот патч её не подбирает.

Ограничения: календарные месяцы/недели распознаются существующим парсером;
привязка к событию использует реплику-источник и границы предложений.
Сложные фразы с несколькими событиями требуют дальнейшего разрешения связей.
