# Основная модель в диапазоне 0,5–1,5 млрд параметров

После уточнения менторов диапазон 500 млн–1,5 млрд считается обязательным.
Новый экстрактор — `Qwen/Qwen3-0.6B`, revision
`c1899de289a04d12100db370d81485cdf75e47ca`, Apache-2.0.
По архитектуре Transformers: 596 049 920 базовых параметров; фактический подсчёт
при загрузке также проверяется скриптом. LoRA обучает адаптер, но вся базовая
модель участвует в извлечении. После слияния адаптера число базовых параметров
не меняется. Старый гибрид RuBERT/ruT5 сохранён для сравнения.

Следующие результаты относятся к **архивному пакету v1**. Текущий пакет — v2.1;
старые утверждения о прохождении порогов к нему не применяются.
Статус новой итерации: [V21_ITERATION.md](V21_ITERATION.md).

Полный двухэпоховый прогон v1 завершён. На внешнем val (383 звонка): precision
0,5233, recall 0,4694, temporal recall 0,4065, state accuracy 0,4398.
Пороги temporal/state пройдены по обеим версиям выданного бейзлайна.
Итоги, сравнения и ограничения — [QWEN_REPORT.md](../reports/QWEN_REPORT.md).

## Установка и воспроизведение

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-qwen.txt
.venv/Scripts/python.exe scripts/download_qwen.py
.venv/Scripts/python.exe scripts/prepare_dev.py
.venv/Scripts/python.exe scripts/run_qwen_iteration.py --epochs 2
```

Последние две команды нужны для воспроизведения обучения и оценок.
Для запуска сохранённого адаптера достаточно установки зависимостей, загрузки
базовой модели и команды API ниже; повторное обучение не требуется.

CUDA-wheel PyTorch устанавливается из официального индекса, как описано в
`EXPERIMENTS.md`. Загрузка весов не отправляет корпус во внешние сервисы.
Если CDN Hugging Face недоступен, официальный аккаунт Qwen на ModelScope:

```powershell
.venv/Scripts/python.exe scripts/download_qwen.py --source modelscope
```

В этом режиме токенизатор/конфигурация остаются закреплены на HF revision,
а SHA-256 файла весов должен в точности совпасть с закреплённым HF-файлом.
Прерванные загрузки возобновляются. `artifacts/qwen_base` исключён из Git;
это около 1,5 ГБ публичных базовых весов. Адаптер и эксперимент сохраняются в
`artifacts/qwen`, окончательный отчёт — `reports/QWEN_REPORT.md`.

## Данные и обучение

- Существующее разделение по аккаунтам: 3334 fit-звонка / 592 dev-звонка;
  внешний `val.jsonl` не используется для обучения или выбора настроек.
- Вход: только `started_at` и реплики с исходными индексами. Разметка,
  будущие звонки и полные идентификаторы аккаунтов на вход не передаются.
- Выход обучения: JSON-массив строк вида
  `[turn_idx, attribute, value, object_type, object_name, polarity]`.
  Это компактный внутренний формат; публичный API возвращает обычные `facts`.
- В fit найдены объекты с типом `other` и именем в виде скрытого ID аккаунта.
  Такие обучающие метки приводятся к допустимому типу и имени из текста либо
  родовому имени («клиент», «услуга», «устройство», «заявка»). Скрытые ID не
  заучиваются как имена; число исправлений записывается в data_audit.
- Длинные звонки разбиваются на окна до 2560 входных токенов с перекрытием
  в две реплики. Метки выбираются по реальным source.turn_idx. Примеры и
  ответы не обрезаются молча: превышение лимита вызывает явную ошибку.
- Потери считаются только по токенам ответа. Проекция в словарь вычисляется
  только для этих позиций, что экономит память на RTX 3060 6 ГБ.
- LoRA rank=16, all-linear, BF16 CUDA, gradient checkpointing, accumulation=8,
  seed=42. Параметры и хэши данных сохраняются в experiment/data_audit.
- Лучший checkpoint выбирается по token loss фиксированных первых 96 звонков
  внутреннего dev. После обучения три варианта дат проверяются на полном dev:
  правила, ranker, ranker с объединением подтверждённых договорённостей;
  целевая функция — temporal_recall + state_accuracy, затем fact F1.
- Выбранный вариант замораживается перед единственной итоговой оценкой val.

Постпроцессор проверяет структуру JSON и реальные индексы реплик, восстанавливает
спаны, ID объектов, даты и переходы состояний. Ошибки генерации и достижения
лимита токенов считаются явно в `generation_diagnostics`. Отказ от предложения
не должен превращаться в договорённость. Неопределённость дат добавляется
API отдельно в `temporal_evidence` — см. `UNCERTAIN_DATES.md`.

Для фрагментов до пяти реплик, если Qwen не нашла кандидатов, есть консервативный
резерв правил: явно названный клиентом тариф из каталога и подтверждённый выезд.
В fit только 41 такой короткий звонок, из них 30 без фактов; модель часто выбирала
пустой ответ на коротком положительном примере. Резерв не является дополнительной
нейросетью и не заменяет Qwen на длинных звонках. Его применение отмечается полем
`generation_diagnostics.short_rule_fallback` и подписью в демо. Другие короткие
формулировки пока могут пропускаться.

Для массовой оценки используется `--batch-size 4`: независимые звонки дополняются
слева, текст и номера реплик разных звонков не смешиваются. На восьми dev-звонках
проверены порядок ответов, схема и отсутствие ошибок JSON. Время пакета, делённое
на число звонков, отражает пропускную способность, а не задержку одного запроса.
Онлайн API обслуживает отдельный звонок; его задержка измеряется отдельно с batch=1.

## Запуск API после обучения

```powershell
$env:PYTHONPATH='src'
.venv/Scripts/python.exe -m compactfacts.api --engine qwen --model artifacts/qwen --base-model artifacts/qwen_base --date-ranker artifacts/date_ranker.joblib --device cuda
```

На полном dev выбран `date_ranker`, без объединения источников договорённостей.
Приведённая команда соответствует этому выбору. Итоговая конфигурация записывается
в `artifacts/deployment.json` после завершения всей проверки.
Выбор объединения договорённостей сохраняется в `artifacts/qwen/inference_config.json`
и автоматически читается экстрактором при использовании ranker.

Для CPU используйте `--device cpu`. Экспериментальная поканальная INT8-квантизация:
`--device cpu --quantized`. На первом checkpoint она ухудшала содержание ответов;
для рабочего запуска используйте BF16 CUDA или FP32 CPU, итоговое сравнение — в отчёте.
Число параметров модели при квантизации не уменьшается — меняется точность хранения и вычислений.

Демо: `http://127.0.0.1:8000/`. `/health` сообщает engine, устройство,
число параметров и имя базовой модели. Базовые веса и адаптер загружаются локально;
генерация идёт с `enable_thinking=False` и без выполнения удалённого кода.

CPU-контейнер (после скачивания базы и обучения):

```powershell
docker build -f Dockerfile.qwen -t zoobears-qwen .
docker run --rm -p 127.0.0.1:8000:8000 zoobears-qwen
```

По умолчанию контейнер использует выбранный на dev ranker дат.
На текущей машине Docker недоступен; сборка и запуск этого образа ещё не проверены.

## Проверки и ограничения

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -v
.venv/Scripts/python.exe scripts/check_qwen_api.py
.venv/Scripts/python.exe scripts/check_predictions.py data/raw/val.jsonl reports/qwen_val_pred.jsonl --output reports/qwen_val_schema.json
```

Pipeline измеряет CUDA BF16 batch=1, CUDA BF16 batch=4, CPU FP32 и экспериментальную
CPU INT8 на одних и тех же 24 dev-звонках. Среднее/p50/p95 включает первый звонок,
но не загрузку модели. В режиме batch=4 это амортизированное время на звонок,
не онлайн-задержка. Контрольное сравнение со старым гибридом — на этих же 24 звонках,
CUDA, batch=1. Выбор настроек проводится на полном dev, внешняя оценка val — bulk batch=4.
CUDA синхронизируется. Пик RSS процесса измеряется средствами ОС и включает
загрузку весов; отдельно сохраняются замеры RSS после звонков. Пик CUDA — выделенная PyTorch
память. Сопоставимые измерения LLM-учителя пока отсутствуют, поэтому сокращение
стоимости в 5/10 раз не заявляется. Метрики нового варианта считаются только
по завершённому запуску, заранее превосходство над старым гибридом не предполагается.
