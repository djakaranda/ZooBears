## Последовательность показа

1. Откройте health: должна быть Qwen,596049920параметров,адаптер qwen_sprint.
2. Загрузите `reports/defense/explicit_transition.json`: заявка принята31марта,
   с4апреля вработе. Первое состояние закрывается4апреля, второе остаётся открытым.
   Источники — реплики2и8. Это пример с явно названными датами.
3. `appointment.json`: звонок14ноября, будущий четверг —19ноября,
   окно визита14:00–18:00, повторное подтверждение объединено.
4. `refusal.json`: отказ клиента не превращается в договорённость, facts пуст.
5. Для неопределённости введите «В прошлом месяце мне подключили тариф Гранд»
   при дате звонка14ноября: API показывает1октября–1ноября, без выдуманного
   точного произнесённого дня. «У меня тариф Гранд» — начало unknown.
6. Покажите таблицу полного val и пороги из итогового отчёта, затем CPU/GPU
   ресурсы. Отдельно подпишите43регрессионных случая, не смешивайте их с val.

Старый шумный `transition.json` не сообщает дату начала всех промежуточных
состояний. У назначенного выезда начало unknown; упоминание субботы относится
к SMS, оно не доказывает переход статуса. Не обещайте этому примеру точную
дату4апреля: такое прежнее утверждение было ошибкой тестового ожидания.

## Как объяснить архитектуру за минуту

Компактная Qwen читает русскую расшифровку и выделяет объект, атрибут, значение,
полярность и источник. Она выбирает ссылки на даты из текущего разговора.
Небольшие CPU-модели уточняют границы состояния; календарные правила связывают
периоды с названными днями. Далее проверяются схема, spans и переходы состояний.
API отделяет точный день от диапазона и неназванного начала. При относительных
периодах конкурсная точка может быть статистической оценкой, что явно отмечено.

Мы не обучали0,6млрд параметров с нуля: дообучили10млн параметров LoRA на
русских размеченных разговорах. Один основной языковой экстрактор, без второго
большого проверяющего на inference. Веса, данные, seed и команды сохранены.

## Ответы на вероятные вопросы

- **Почему можно доверять метрикам?** Полный новый прогон383val-звонков,
  оригинальный оценщик v2.1, отдельная проверка JSON/источников. Но val уже
  анализировался ранее; скрытый тест остаётся независимой проверкой.
- **Откуда выигрыш?** Целевые короткие примеры и более согласованная работа с
  границами дат/состояний. Сравнения вариантов выполнены на полном dev.
- **Воспроизводимость?** Сохранены адаптер, конфигурация, fit-модели, SHA,
  разбиение и параметры. Метрики повторяются одним способом inference;
  побитовая идентичность разных GPU/CPU не гарантируется.
- **Сокращение затрат?** Размер модели соответствует диапазону0,5–1,5млрд;
  параметрическая ветка обоснована отдельно. Сопоставимого замера денег и
  GPU-времени учителя нет, поэтому десятикратное ускорение не заявляем.
- **Дообучение без ручной разметки?** План: сохранять реальные обезличенные
  обращения, фильтровать уверенные псевдометки самой модели, спорные факты
  выборочно проверять большой моделью и дообучать LoRA. Контрольный dev
  защищает от падения качества. Этот производственный цикл пока не реализован.
- **Новые атрибуты и языки?** Расширить схему/каталог, добавить целевые примеры,
  обучить новый адаптер и проверить источники/даты на отдельном dev.
  Русский поддерживается и проверен; другие языки не оценивались.
