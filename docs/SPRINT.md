## Данные и обучение

Набор из архива `data/regression/ZooBears_tests_v2_1.zip` содержит 43 сценария.
Он используется для регрессионных проверок, не для обучения. На исходной для
этой итерации версии полностью проходили16/43. Это синтетические проверки;
их метрики не заменяют официальные dev/val. Два сценария воспроизводят известный
TypeError официального оценщика и отдельно отмечаются его проверяющим скриптом.

Для продолжения LoRA выбраны 800 реальных fit-звонков и созданы640 отдельных
синтетических разговоров: короткие факты, действия, состояние услуг, три статуса
одной заявки, тарифные переходы, разные устройства, принятие и отклонение
предложений. Точные диалоги нового набора и dev исключены; аккаунты dev также
не пересекаются с fit. Все800 синтетических фактов имеют корректные источники.
Точные размеченные даты проверены на присутствие в таблице дат разговора.

После защищённой ASR-аугментации3%: 1545 окон, 1826213 токенов, 165730 целевых
токенов. У обрезания целевых ответов нет допустимого режима — превышение
лимита приводит к ошибке. Использован прежний формат и прежняя нумерация дат.

Продолжение сохранённой LoRA: rank16, 10092544 обучаемых параметра, одна эпоха,
LR2e-5, seed73, BF16 CUDA, batch1, accumulation8, gradient checkpointing,
AdamW с weight_decay0.01, clip1. Наблюдаемые ссылки на даты имеют вес3.
Новый optimizer; состояние старого optimizer не возобновляется.

## CPU-обработчики дат

Сравниваются заранее перечисленные варианты, включая исходный. Границы
ранжируются по локальной части реплики, положению события и следующим
состояниям того же объекта. Если точный эталонный день отсутствует среди
допустимых кандидатов fit, такой пример не переименовывается в «открытое
состояние»: он пропускается при обучении соответствующей границы.

Линейная модель и деревья обучены только на fit и новых синтетических примерах.
На dev выбирается конфигурация; val не участвует в обучении этих моделей.
Есть ограничения по recall/F1 и State. Сам официальный оценщик не изменён;
совместимый обход его известной ошибки используется только на dev.

Календарные правила обрабатывают произнесённые дни словами и пересечение
«следующая неделя» + «понедельник», «следующий месяц» + конкретное число.
Это отдельный постпроцессор: таблица индексов, на которой обучалась Qwen,
не меняется. API сохраняет цитаты, обосновывающие вычисленный день.

Отдельный эксперимент с неполными периодами выбирает точечную оценку ВНУТРИ
произнесённого диапазона по статистике fit. Это НЕ точная дата, названная
говорящим. В `temporal_evidence` сохраняется диапазон, оценка и её метод.
Уже находящаяся внутри диапазона дата не заменяется такой оценкой.

## Воспроизведение

Сначала установить зависимости и скачать закреплённую базу по docs/QWEN.md,
подготовить account-disjoint split командой `scripts/prepare_dev.py`.
Для эксперимента использовать отдельный клон, сохраняя готовый рабочий адаптер.

```powershell
.venv/Scripts/python.exe scripts/prepare_sprint.py
.venv/Scripts/python.exe scripts/fit_sprint_dates.py
.venv/Scripts/python.exe scripts/run_sprint.py
```

`--resume` предназначен для машины с сохранёнными tmp и checkpoints. Состояние
этапов: `reports/sprint_status.json`; журналы: `tmp/sprint_logs`. Веса и
конфигурация val фиксируются контрольными суммами: после изменения выбранной
модели или постпроцессора прежние результаты val не переиспользуются.

Для настройки Windows используется временный запрос активности системы и
дисплея; после выхода процесса он снимается. На этом ноутбуке погасший дисплей
сопровождался ограничением GPU30Вт. Постоянная схема питания не меняется.

CPU-проба отдельного date-only verifier — исследовательский эксперимент,
не включённый по умолчанию в рабочую модель. Его вход содержит только текст
и идентичность предсказанных фактов, без их дат и без gold.
